# Plan 19.2: Bits (stages over a capture) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From a stored burst capture, one operation builds a chain that replays the capture, demodulates it, recovers the clock, slices bits and reports framing hypotheses, so an agent or the operator reads an unknown signal's bits and the candidates for its sync word, frame period, line code and CRC.

**Architecture:** Eight new stage kinds in `zeta-dsp` (`capture_in`, `resample`, `fsk_demod`, `psk_demod`, `ook_demod`, `clock_recover`, `slicer`, `correlate`, `bit_view`) plus a CRC table; two new ops in `zeta-core` (`graph_start`, the generic job-from-a-graph with no radio, and `bits_start`, the shorthand that builds the chain from a capture's feature record) on a leaseless record whose source is `node`, as a `mix` is; a Bits pane on the page; the "Working layer 4" field craft rewritten as the executable playbook. Demodulated decision signals and symbol streams travel as `audio` frames, bits as `event` frames in the plan-16 shape; no new stream kind. Seams between captures travel in-band as time discontinuities, so every stage resets on one and no stage needs a second input.

**Tech Stack:** Rust (tokio, serde, schemars, rustfft already in `zeta-dsp`), the `synth` fsk/psk/ook families for fixtures, vanilla JS page with the Playwright e2e suite in `crates/zeta-ui/tests/e2e/ui.py`.

**Spec:** `docs/superpowers/specs/2026-11-02-layer4-explore-design.md`, sections 6 (all of it), 8 (the 19.2 lines), 10 and 11 (calls 6, 7, 8, 14). Section 7 is plan 19.3; nothing here starts it (no `frame_decode`, no proposals, no signatures).

## Global Constraints

- Every op field is required and unknown fields are rejected (`deny_unknown_fields` on `Op`); a nullable op field uses `#[serde(deserialize_with = "crate::modes::nullable")]` plus `#[schemars(required, schema_with = "crate::types::nullable::<T>")]` as `MixStart.sources` does (`crates/zeta-core/src/ops.rs`); `Baud` and `u8` fields use `nullable_u64`-style helpers already in `ops.rs`.
- Stage params: a param that depends on the signal (`symbol_rate_baud`) is required; every other param has a `#[serde(default = "...")]` so `stage_params_schemas_are_strict` (`crates/zeta-dsp/src/lib.rs`) passes and stored graphs keep loading. Every stage is registered in `zeta_dsp::register_all` and so listed by `schema` under `stages`.
- A `bits` event is at most 64 KiB (plan 16): `slicer.chunk_bits` is bounded so the hex alone is at most 32 KiB.
- Numbers from the spec are named constants, never literals in logic: `SAMPLES_PER_SYMBOL = 8`, `MIN_SAMPLES_PER_SYMBOL = 4`, `LOOP_PAUSE_MS_DEFAULT = 500`, `WINDOW_BITS_DEFAULT = 65536`, `CHUNK_BITS_DEFAULT = 4096`, `CONSTELLATION_POINTS_MAX = 512`, `CRC_MIN_FRAMES = 3`, `HYPOTHESES_BUDGET_MS = 200`, `SYNC_CANDIDATES_MAX = 5`, `PERIOD_CANDIDATES_MAX = 3`.
- Every stage resets its streaming state on a time discontinuity: a frame whose `provenance.span.start_ns` is more than one sample period from the previous frame's `end_ns` (the seam `capture_in` makes between two captures, a lag, a restart). `slicer` flushes its chunk at a seam so a `bits` event never spans one; `bit_view` never correlates across one.
- `AGENTS.md` and `skills/zetasdr/SKILL.md` are generated: after any op, flag, stage or field-craft change run `cargo run -p zeta -- agents-md --check`, regenerate (`cargo run -p zeta -- agents-md > AGENTS.md`, `cargo run -p zeta -- agents-md --skill > skills/zetasdr/SKILL.md`) and commit the result in the same commit.
- Node tests write captures into the node's own store (`node.bursts().write(NewCapture {..}, &samples)`, as `crates/zeta-core/tests/capture_ops.rs` does) from IQ synthesised by `zeta_dsp::synth` (`SynthSpec::Fsk`, `Psk`, `Ook`, `synthesise`); no live hardware in any test.
- The node runs, and every test passes, with no captures, no station and no network.
- `cargo fmt -p <member> -- --check` per member (the nested worktree breaks `cargo fmt --all`), `cargo clippy --workspace --all-features -- -D warnings`, and the gate `cargo test --workspace --all-features --no-fail-fast` green with no `ui e2e skipped` line, before the plan is called done. Builds share `/Projects/ZetaSDR/target` (`.cargo/config.toml` in the worktree); before a long task prune with `find /Projects/ZetaSDR/target/debug/deps -maxdepth 1 -type f ! -name '*.*' -mmin +45 -size +20M -delete`.
- Commits go on this branch (`worktree-plan19-2`); one commit per task, message in the repo's style (`Area: what changed`), no trailer.

## Review Focus

Inputs the spec implies but no obvious test exercises; each gets a test in the task that owns the code:

1. A capture set whose windows differ in rate or centre (a watch that re-centred between two windows) must be refused naming the capture, never replayed as one garbled stream. (Task 2: `a_mixed_rate_set_is_refused_naming_the_id`; Task 10: `bits_start_refuses_a_set_of_mixed_rates`.)
2. A symbol rate the capture cannot hold (over a quarter of its rate) must be refused at `bits_start` naming the rate the capture holds, not fail the job at launch. (Task 10: `bits_start_refuses_a_rate_the_capture_cannot_hold`.)
3. A `loop: false` chain must deliver its last `bits` chunk before the job ends `stopped`: the root ending must not cancel the slicer mid-chunk. (Task 2: `replays_two_captures_back_to_back_with_a_segment_at_each_seam` asserts the pause after the last frame; Task 10: `a_one_pass_chain_ends_stopped_with_its_last_chunk_delivered`.)

(Task 9: `graph_put_on_a_graph_job_relaunches_without_a_radio`, `a_graph_job_resumed_on_an_expired_capture_fails_naming_it`.)

### Task 5: `slicer`

**Files:**
- Create: `crates/zeta-dsp/src/slicer.rs`
- Modify: `crates/zeta-dsp/src/lib.rs`
- Test: `crates/zeta-dsp/src/slicer.rs` tests module

**Interfaces:**
- Produces: `pub const SLICER_KIND: &str = "slicer"`; `pub const CHUNK_BITS_DEFAULT: u32 = 4096`; `pub const CHUNK_BITS_MAX: u32 = 131_072` (32 KiB of hex); `pub const CONSTELLATION_POINTS_MAX: usize = 512`; `pub const CONSTELLATION_EVERY_MS: u64 = 1000`; `#[serde(rename_all = "snake_case")] pub enum Constellation { Bpsk, Qpsk, Psk8 }` (wire `8psk` via `#[serde(rename = "8psk")]`); `pub enum Mapping { Natural, Gray }`; `#[serde(deny_unknown_fields)] pub struct SlicerParams { #[serde(default = "default_levels")] pub levels: u8, #[serde(default)] pub constellation: Option<Constellation>, #[serde(default)] pub mapping: Mapping, #[serde(default)] pub differential: bool, #[serde(default = "default_chunk_bits")] pub chunk_bits: u32 }` (`check_params`: `levels: 2 or 4`, `chunk_bits: 1..=131072`); `pub struct SlicerStage` (inputs `[Audio]`, outputs `[Event]`); `pub fn bits_event(rate_baud: u32, bits: &[u8], offset_bits: u64, t_ns: u64) -> serde_json::Value` (the plan-16 shape `{"protocol": "bits", "rate_baud", "bits": <hex, MSB first, last byte zero-padded>, "count", "offset_bits", "t_ns", "summary": "<count> bits at <rate> Bd"}`; `offset_bits` is the first bit's index since the last seam, an addition to the plan-16 shape the page and `correlate` use); `pub fn bits_from_hex(hex: &str, count: usize) -> Vec<u8>`.
