# Subjects Implementation Plan (plan 23)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A mode row names what its events are about, so the page shows one table row, one marker and track, and at most one waterfall line per aircraft, station or sonde; and the agent may stop the jobs it started in the same run.

**Architecture:** An optional `subject` block on `ModeRow` (and `alt_unit` on `position`) drives everything. A new page module `subjects.js` holds the row cache and a store keyed by (job, key), fed from `ov.onEvent`; the Subjects pane, `overlays.js` ribbons and `map.js` all read that store. No node-side state. The agent keeps a per-run set of its own job ids in `Agent::turns` and lets `job_stop` of those past the unchanged `gate`.

**Tech Stack:** Rust 2024 (serde, schemars), `FakeLlm`/`RecordingExecutor` (`crates/zeta-agent/src/fake.rs`), vanilla ES modules in `crates/zeta-ui/web`, vendored Leaflet, Playwright (`crates/zeta-ui/tests/e2e/ui.py`), `fake_lines` (`crates/zeta-ext/tests/fake_lines.py`).

**Spec:** `docs/superpowers/specs/2026-11-02-subjects-design.md` (read it first; section numbers refer to it). Where this plan departs from it, "Rulings on the spec" at the end says why. Those rulings bind.

## Global Constraints

- New row fields are optional and `null` by default; every struct `deny_unknown_fields` with `transform = require_all`, as `PositionMap` (`row.rs:84-94`). A broken `subject` makes that row `broken` with `<field>: <error>`.
- Field shape: `subject: {key, name, waterfall: summary|fold, columns: [{field, label, unit}], heading, label}`. `unit` is `ft|m|kt|km_h|m_s|deg|null`. `position.alt_unit` is `m` (default) or `ft`; 1 ft = 0.3048 m, 1 kt = 1.852 km/h, 1 m/s = 3.6 km/h.
- Display: `6401 m`, `780 km/h`, `245°`; position `-27.39, 152.43`; last seen `12 s`; distance `14.8 km, 47°`; unwatched `not watched (limit 4)`; section `<job kind> <source>, <n> <name>` (`adsb_decode b210, 12 aircraft`); summary line `<row.protocol> <n> <name>, last <label>`.
- Values: dim `subject_dim_s` default 60, drop `subject_drop_s` default 300, timer 1 s, track 100 fixes for a keyed row (`SUBJECT_TRACK_POINTS`); `TRACK_POINTS` 3600 stays for unkeyed rows.
- A key that is null, absent or blank (`String(v).trim() === ""`) makes the event unkeyed: it behaves exactly as today. A job with an `owner` (a watch's or identify's trial) is never in the store.
- All DOM from data uses `textContent`, including the Leaflet icon (pass `divIcon` an element, never an HTML string). No new asset is fetched. No per-protocol code on the page.
- Gates per task: `cargo fmt -p <crate> -- --check` for each touched crate (per-member, the nested worktree breaks `--all`), `cargo clippy --workspace --all-targets --all-features -- -D warnings`, the touched crates' tests. Page tasks also run the new scenarios: `cargo test -p zeta --test ui` runs all of ui.py. Temp files under the job's tmp directory, never `/tmp`; Python via `python3 -I` except Playwright.
- Guide regeneration, `cargo run -p zeta -- agents-md > AGENTS.md` and `cargo run -p zeta -- agents-md --skill > skills/zetasdr/SKILL.md`, lands in **Tasks 1, 4 and 5**. Tasks 2, 3 and 6 change no guide input and must leave `agents-md --check` passing untouched.
- Commits on `worktree-subjects`, one per task, with the message each task names, each ending with a blank line and the session attribution line the harness gives. No merge and no deploy in this plan.

## Review Focus

1. **A later message must not erase an earlier one.** dump1090 sends every field, `null` when the message does not carry it; a velocity message must keep the callsign, an `alt_m: null` fix must keep the altitude, and an altitude of `0` and a heading of `0` are values, not blanks. Pinned in Task 2 (`scenario_subjects_store_merge_units_and_fill`).
2. **Decoder text is hostile.** A callsign or ACARS text holding `<b>` shows literally in the table, tooltip, ribbon, marker label and popup. Pinned in Tasks 2, 3, 4 (the fixture's `<b>JST3</b>`).
3. **A source switch neither loses nor double-counts.** A job moves between the ordinary watch and the positioned watch; subjects stay and counts do not jump, and a keyed row with no `position` on another source is followed too. Pinned in Task 2 (`scenario_subjects_survive_a_source_switch`).
4. **More subject jobs than sockets.** The oldest fifth job is named as not watched, not silently empty. Pinned in Task 2 (`scenario_subjects_name_the_jobs_not_watched`).
5. **Events before the row is known.** A slow `modes_show` must not flash a ribbon per message. Pinned in Task 3 (`scenario_slow_row_lookup_draws_no_ribbon_per_message`).

Wide: `#waterfall` takes the left half; with only one of map and table on, it takes the right half; with both, the map the top of the right half and the table the bottom.
