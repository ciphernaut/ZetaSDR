# Decoders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Four more protocols a job can decode to typed events, each also proving a layer-2 label by decode-to-identify: POCSAG pagers, RDS from broadcast FM, ADS-B via dump1090 as an external process, and ACARS.

**Architecture:** Every decoder is one stage over the `channel` stage's IQ output (it demodulates internally, so the same pure functions serve the stage and `DecodeToIdentify`), a `JobKind` that composes `channel → <kind>` exactly as `aprs_decode` does, a CLI value, a guide note, a UI menu entry and a ribbon format. POCSAG, RDS and ACARS are native Rust in `zeta-dsp` with modulator fixtures and, where the program is installed, an oracle test against `multimon-ng` or `acarsdec`. ADS-B lives in a new crate `zeta-ext` that spawns `dump1090` (GPL, so behind a process boundary: design 4.8) with IQ on its stdin at 2.4 Msps and reads its BaseStation (SBS) CSV from a loopback TCP port. The catalogue names the job kind that proves each signature in `Signature.decoder`.

**Tech Stack:** Rust 2024 (`zeta-dsp`, `zeta-core`, new `zeta-ext` with `tokio::process`), `zeta-ui` vanilla JS, Playwright scenarios in `crates/zeta-ui/tests/e2e/ui.py`, dump1090 / multimon-ng / acarsdec as optional test oracles and runtime (dump1090 only).

**Spec:** `docs/superpowers/specs/2026-10-18-zetasdr-design.md` sections 2 (stories: "set up a background decoder for all ACARS and ADS-B activity"), 4.4 (signatures name "which decoder plugin proves it"), 4.8 (GPL decoders behind the process boundary), 5.1 (high-level operations for the common stories), 6.2 (decode-to-identify: "run the decoder plugin and see whether its CRC or framing passes"), 7 (decoded text as ribbons pinned to their channel).

## Global Constraints

- `zeta-core` gains no dependency and no DSP; new job kinds are `JobKind` variants composing existing stage kinds by name: `pocsag_decode`, `rds_decode`, `adsb_decode`, `acars_decode`. Each is `channelised()`; graph = `channel` (`center_hz`, `bandwidth_hz`, `out_rate_hz` = the `out` already computed in `expand`) → `<kind>` with params `{}`; edge kind `iq`. `deviation_hz` and `sideband` must be `null` for all four (the existing check).
- Every event carries `"protocol"` as its first key (`"pocsag"`, `"rds"`, `"adsb"`, `"acars"`), as `aprs_decode` does. Event shapes are fixed in the task that produces them; the UI task consumes them verbatim.
- Decode-to-identify labels: `layer: 2`, `confidence: 1.0`, `name` one of `APRS`, `POCSAG`, `RDS`, `ACARS`; evidence names what passed (count of CRC/BCH-clean units and the first identity). A decoder that passes nothing emits no label. ADS-B is not attempted by `DecodeToIdentify` (it needs a 2.4 Msps block and an external program).
- No stage spawns a program named by a job parameter. `adsb_decode` runs the program the binary found at startup (`ZETA_DUMP1090` absolute path, else the first of `dump1090`, `dump1090-fa`, `dump1090-mutability`, `readsb` on `PATH`), with a cleared environment plus `PATH`, `HOME`, `LANG`, `LC_ALL`, `LC_CTYPE`, `TERM`, `kill_on_drop`, and it is reaped on every exit path (as `zeta-plugin/src/host.rs` does).
- `cargo test` passes with none of dump1090, multimon-ng or acarsdec installed: oracle tests print `skipped: no <program>` and pass; the ADS-B wiring test uses a fake program shipped in the crate's `tests/`.
- Python run by tests uses `python3 -I` except the Playwright runner (which stays plain `python3`).
- AGENTS.md and `skills/zetasdr/SKILL.md` are regenerated (`cargo run -q -p zeta -- agents-md > AGENTS.md`, `-- agents-md --skill > skills/zetasdr/SKILL.md`) in every task that changes an op, a kind or a note; `cargo test -p zeta --test agents_md --test transports` checks them.
- Gate per task: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, the crate's tests. Final gate adds `cargo test --workspace --no-fail-fast` (no `FAILED`, no `ui e2e skipped`).

## Review Focus

1. A decoder fed a channel whose rate is not what it assumes (a `channel_rate_hz` result such as 200 781 Hz for RDS, 53 333 Hz for POCSAG) must still decode: every demodulator derives its timing from the first frame's `sample_rate_hz`, never from a constant. Pinned by the "odd rate" roundtrip test in Tasks 1, 3 and 6.
2. Inverted polarity (an FM discriminator's sign depends on the tuning side): POCSAG and RDS must decode either polarity. Pinned in Tasks 1 and 3.
3. A burst split across stage input frames: a message whose bits straddle a 100 ms frame boundary must decode. Pinned by feeding fixtures in 4 800-sample chunks (Tasks 2, 4, 7).
4. dump1090 absent or dying mid-run: the job fails with a reason naming the program and the exit status; the stage never hangs on a closed socket or a full stdin pipe. Pinned in Task 5.
5. Noise-only input must produce no events and no labels for any of the four decoders (no false POCSAG from random bits: the sync word plus one BCH-clean address codeword are both required). Pinned by a noise test in each codec task.

**Files:**

**Interfaces:**
- Consumes: `crate::nbfm::nbfm_demod(iq, rate_hz, deviation_hz, &mut prev) -> Vec<f32>`; `crate::fixtures::{nbfm_modulate, awgn}`.
- Produces (all `pub`):
  - `pub const SYNC: u32 = 0x7CD2_15D8; pub const IDLE: u32 = 0x7A89_C197; pub const BAUDS: [u32; 3] = [512, 1200, 2400]; pub const DEVIATION_HZ: u64 = 4_500;`
  - `pub fn bch_ok(codeword: u32) -> bool` — true when the BCH(31,21) remainder (generator `x^10+x^9+x^8+x^6+x^5+x^3+1`, i.e. `0x769`, over bits 31..1) is zero and bit 0 makes the 32 bits even parity. No error correction.
  - `#[derive(Clone, Debug, PartialEq, Serialize)] pub struct PocsagMessage { pub address: u32, pub function: u8, pub baud: u32, pub kind: PocsagKind, pub text: String }` with `#[derive(Serialize)] #[serde(rename_all = "lowercase")] pub enum PocsagKind { Numeric, Alpha, Tone }`.
  - `pub struct PocsagDecoder` with `pub fn new(baud: u32) -> Self` and `pub fn feed(&mut self, bits: &[u8]) -> Vec<PocsagMessage>` — streaming over NRZ bits (0/1): finds `SYNC` (or its complement, then decodes the rest inverted), takes 16 codewords per batch, address codeword = bit 31 clear, address `((cw >> 13) & 0x3FFFF) << 3 | frame_index`, function `(cw >> 11) & 3`; message codewords (bit 31 set) accumulate 20 data bits each until the next address codeword, idle or lost sync; function 0 → `Numeric` (4-bit nibbles, bit-reversed, table `"0123456789*U -)("`), function 3 → `Alpha` (7-bit ASCII, LSB first, dropping control characters other than `\n`), 1 or 2 with no message codewords → `Tone`. A codeword failing `bch_ok` ends the current message (emitted if any data) and skips to the next codeword; two consecutive failures drop sync.
  - `pub struct BitSync` with `pub fn new(rate_hz: u64, baud: u32) -> Self` and `pub fn feed(&mut self, nrz: &[f32]) -> Vec<u8>` — DC removal (one-pole high-pass, 1 Hz) then a zero-crossing-adjusted sampler: a bit per `rate/baud` samples, phase nudged by 1/8 of a bit toward each zero crossing.
  - `pub fn decode_pocsag_iq(iq: &[Complex<f32>], rate_hz: u64) -> Vec<PocsagMessage>` — `nbfm_demod` at `DEVIATION_HZ`, then for each of `BAUDS` a `BitSync` and a `PocsagDecoder`; returns the union (a message's `baud` says which decoder).
  - fixtures: `pub fn pocsag_encode(messages: &[(u32, u8, &str)], baud: u32) -> Vec<u8>` — bits: 576 preamble bits `1010…`, then batches of `SYNC` + 8 frames × 2 codewords, each message's address codeword in frame `address & 7` (idle codewords fill the rest), message codewords (numeric for function 0, alpha for 3) following, BCH and parity computed by the encoder's own routine (not `bch_ok`); `pub fn pocsag_modulate(bits: &[u8], baud: u32, audio_rate_hz: u32) -> Vec<f32>` — NRZ `+0.8`/`-0.8`, `audio_rate/baud` samples per bit rounded to nearest (document that 48 000/512 = 93.75 rounds to 94: the fixture's rate is then 510.6 baud, inside what `BitSync` tracks); `pub fn pocsag_packet_iq(address: u32, function: u8, text: &str, baud: u32, iq_rate_hz: u32, offset_hz: f64) -> Vec<Complex<f32>>` — 0.3 s silence, the modulated bits, 0.3 s silence, through `nbfm_modulate(audio, 48_000, iq_rate_hz, 4_500.0, offset_hz)`.

  - `pub struct RdsDemod` with `pub fn new(rate_hz: u64) -> Result<Self, String>` and `pub fn feed(&mut self, composite: &[f32]) -> Vec<u8>` — resamples to `RDS_RATE_HZ` if `rate_hz != RDS_RATE_HZ`; band-pass 19 kHz ±100 Hz → second-order PLL on the pilot → 57 kHz reference as 3× the PLL phase; mixes the 57 kHz band (±2.4 kHz band-pass first) to baseband; low-pass 2.4 kHz; symbol timing at `BAUD` by an early-late gate; biphase: each bit is two half-symbols of opposite sign, decided by the sign of (first half − second half); differential decode (`out = in ^ prev`). Output: data bits, one per symbol.
  - `pub struct RdsSync` with `pub fn feed(&mut self, bits: &[u8]) -> Vec<[u16; 4]>` — slides over bits keeping the last 104; when four consecutive 26-bit blocks have offsets A, B, C or C', D, emits the four 16-bit data words and advances 104 bits; otherwise advances 1 bit; once synced it stays block-aligned until two consecutive groups fail.
  - `#[derive(Default)] pub struct RdsState { pi: Option<u16>, pty: u8, tp: bool, ps: [Option<char>; 8], rt: [Option<char>; 64], rt_ab: Option<bool> }` with `pub fn apply(&mut self, group: [u16; 4]) -> Option<RdsEvent>`: PI = block A; group type = `B >> 12`, version = `(B >> 11) & 1` (0 = A); PTY `(B >> 5) & 0x1F`; TP bit 10. Type 0 (A or B): segment `B & 3`, two chars from D into `ps[2*seg..]`. Type 2A: segment `B & 0xF`, four chars from C and D into `rt[4*seg..]`; 2B: two chars from D into `rt[2*seg..]`; the A/B flag `(B >> 4) & 1` clears `rt` when it changes. Returns `Some(event)` when PS becomes complete (all 8) or changes once complete, or when RT gains a `\r` terminator or fills, or when PI changes; the event is the current state.
  - `#[derive(Clone, Debug, PartialEq, Serialize)] pub struct RdsEvent { pub pi: String /* 4 upper hex */, pub pty: u8, pub tp: bool, pub ps: Option<String>, pub rt: Option<String>, pub group: String /* e.g. "0A" */ }`.
  - `pub fn decode_rds_iq(iq: &[Complex<f32>], rate_hz: u64) -> Vec<RdsEvent>` — discriminator → `RdsDemod` → `RdsSync` → `RdsState`.
  - fixtures: `pub fn rds_group_bits(pi: u16, ps: &str, rt: &str) -> Vec<u8>` — 4 × type 0A groups (PS) then 16 × type 2A groups (RT, padded with spaces to 64, A/B flag 0), each block data+checkword with its offset, repeated 3 times, then differential-encoded (`tx = bit ^ prev_tx`); `pub fn rds_composite(bits: &[u8], rate_hz: u32, audio: &[f32]) -> Vec<f32>` — biphase symbol per bit (`+h −h` for 1, `−h +h` for 0, `h` a raised-cosine half-symbol), 57 kHz carrier phase-locked to a 19 kHz pilot (pilot amplitude 0.09, RDS 0.03, audio 0.6); `pub fn wfm_modulate_composite(composite: &[f32], rate_hz: u32, deviation_hz: f64) -> Vec<Complex<f32>>` — FM at 75 kHz with no further filtering; `pub fn rds_station_iq(pi: u16, ps: &str, rt: &str, iq_rate_hz: u32) -> Vec<Complex<f32>>` composing the three with a 1 kHz tone as audio.
