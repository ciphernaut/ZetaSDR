# Mode Registry Implementation Plan (plan 16)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A decoder mode is a data row the node loads, validates, lists and tests (`modes_list`, `modes_show`, `zeta modes check`); one declarative `external_decode` stage runs external programs declared in a row, with `adsb_decode` as the first program row and an OpenWebRX-style handler report at startup; every decoded event carries the common envelope (`protocol`, `summary`, `t_ns`); `classify` tries the plausible rows in catalogue-score order and reports what it tried; a new `identify` job works through every plausible row and ends with a verdict; the `video` payload and plugin protocol 2 are settled. No new mode ships.

**Architecture:** `zeta-core` gains `src/modes/` (row schema, registry with embedded rows under `modes/*.json` plus an operator directory, graph-template expansion, summary templates, scoring) and `JobKind::Mode(ModeId)` for operator rows; the four in-crate decoder kinds expand from their rows and are pinned byte-for-byte. `zeta-ext` becomes the adaptor crate: `external_decode` (params `{mode}` only), the output parsers, shared process plumbing, and `adsb_decode` as an alias stage over the ADS-B row. `zeta-dsp` keeps the quick attempts (`identify.rs`) and gains the ungated synthesiser (`synth.rs`) the rows' tests use; `DecodeToIdentify` and `CatalogueClassifier` read the registry. `identify` is a controller job like `scan`: a loop in `node/launch.rs` that starts the candidate modes as child jobs inside its own lease, one at a time, and publishes `candidate` events. The page renders `summary` and gains one menu entry.

**Tech Stack:** Rust 2024 (`zeta-core`, `zeta-dsp`, `zeta-ext`, `zeta-plugin`, `zeta-ws`, `zeta`), serde/schemars, tokio; vanilla JS in `crates/zeta-ui/web`; Playwright scenarios in `crates/zeta-ui/tests/e2e/ui.py`. No new dependency: rows are JSON (serde_json is already in `zeta-core`).

**Spec:** `docs/superpowers/specs/2026-10-27-mode-registry-design.md` (sections 4 registry, 5 adaptor, 6 synthesiser, 7 sweeps, 8 envelopes, 9 builder's calls, 10 live acceptance).

## Global Constraints

- No new crate dependency anywhere. Row files are JSON throughout (builder's call made: no TOML), one file per mode under `modes/` in the repo, embedded with `include_str!`; the operator directory is `--modes-dir PATH` (default `$XDG_CONFIG_HOME/zetasdr/modes`, else `~/.config/zetasdr/modes`); an operator file with an embedded `id` replaces that row.
- AGENTS.md rules: one unit per field (`_hz`, `_baud`, `_ns`, `_ms`, `_db`), every field required unless the spec marks it optional, unknown fields rejected (`deny_unknown_fields` on every row struct), errors carry `field` and the acceptable values, ids never invented (`job_start` with an unknown mode id fails `unknown { field: "kind", value, known }` (built-in kinds plus row ids)).
- A bad row or a missing program never stops the node: `broken`/`unavailable` state, one stderr line each at startup (`zeta: mode <id> (<file>): <field>: <error>`; handler lines per spec 5.3). zeta never fetches or builds a program.
- Op results are additive, with one exception the spec's shape forces: `classify`'s result changes from the bare `labels` array to `classification { labels, tried }` (Task 6 updates every reader: `menu.js`, `agent.js`, the tests). Every other new field is additive. Event payloads gain `summary` and `t_ns`; `protocol` values stay what they are today (`aprs`, `pocsag`, `rds`, `acars`, `adsb`), carried by the row's `protocol` field.
- Pinned graphs: `aprs_decode`, `pocsag_decode`, `rds_decode`, `acars_decode` expand from their rows to graphs `graph::same_pipeline`-equal to today's (`crates/zeta-core/src/ops.rs:727-852`). `adsb_decode` is the exception: behaviour pinned, graph changes to `channel` → `external_decode`.
- `external_decode` params are `{ "mode": "<id>" }` only; the program block is resolved from the loaded registry at launch. Programs run with the cleared environment (`PASS_ENV` of the plugin host: `PATH`, `HOME`, `LANG`, `LC_ALL`, `LC_CTYPE`, `TERM`, `PYTHONPATH`, plus `ZETA_PLUGIN_ENV_*` mapped and `PYTHONUNBUFFERED=1`), a process group killed on drop, stderr prefixed `[<mode>]`.
- Constants: `CLASSIFY_TRIES = 5`; `MIN_SPAN_MS_DEFAULT = 1000`; identify measures for `IDENTIFY_MEASURE_MS = 1000`; handler version probe bound `HANDLER_VERSION_TIMEOUT = 2 s`; existing `ADSB_BANDWIDTH_MIN_HZ = 2_000_000`, `ADSB_RATE_HZ = 2_400_000`, `RDS_MIN_BW_HZ = 150_000`, `RDS_MIN_MEASURED_BW_HZ = 100_000` keep their values, now carried by the rows (`band.bandwidth_hz`, `identify.min_span_ms`) where the spec moves them.

## Review Focus

1. **An operator row with a typo must not take a built-in down.** A `modes/` file whose `id` matches `pocsag_decode` but fails validation leaves the embedded `pocsag_decode` row in force and reports the file as `broken`. Pinned in Task 1 (`a_broken_override_leaves_the_embedded_row_in_force`).
2. **A program that prints garbage must not kill the job.** An `external_decode` whose parser cannot parse a line skips it and counts it (`job_context` `external.unparsed`), and only a child exit fails the stage. Pinned in Task 4 (`unparsable_lines_are_counted_not_fatal`).
3. **`identify` must leave the radio as it found it.** A stopped `identify` (operator stop, or `unknown`) leaves no child job running and no lease held; a proof leaves exactly one child job, named in the verdict. Pinned in Task 7 (`identify_stop_leaves_no_child_and_no_lease`, `a_proof_leaves_one_named_child`).
4. **A row whose `summary` names a missing field must render, not throw.** A `{field}` absent from an event renders as empty with its separator dropped under `?`, and as the literal `null` otherwise; the page never shows `undefined`. Pinned in Task 3 (`summary_with_a_missing_field_renders_empty`).
5. **`classify` on a short box must still try something.** A 1.0 s selection tries every row with `min_span_ms <= 1000`; a 0.5 s selection reports every row `skipped_span` and still returns the layer-1 label. Pinned in Task 6 (`a_short_selection_reports_skipped_span_and_a_layer1_label`).
