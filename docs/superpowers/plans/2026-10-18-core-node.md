# ZetaSDR Core Node Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A headless ZetaSDR node that can load a SigMF file as a source, keep an IQ history, run persistent jobs described by graph documents, and expose every operation through a `zeta` CLI, with a test suite that passes with no hardware attached.

**Architecture:** A Cargo workspace. `zeta-core` holds the types, the port trait with leases, the ring buffer, the stream bus, the graph document, the job runtime, the operation set and the plugin traits; it imports no driver or vendor library. `zeta-source-file` is the first port plugin. `zeta` is the CLI binary that embeds a node. Plugins are compiled-in trait objects registered at startup; dynamic loading is deferred. Persistence is JSON files under a state directory.

**Tech Stack:** Rust 1.97 (present on the dev box), tokio, serde + serde_json, schemars (JSON schema for the operation set), clap, thiserror, num-complex, tempfile (tests). No GNU Radio, SoapySDR, or model client in any crate this plan touches.

**Spec:** `docs/superpowers/specs/2026-10-18-zetasdr-design.md`

## Global Constraints

- `zeta-core` must not depend on any SDR driver, DSP framework, GUI toolkit or LLM client crate (design: anti-goal "no privileged backend / vendor"). Enforced by a test that reads `crates/zeta-core/Cargo.toml`.
- Every frequency, bandwidth and rate field is an integer in a field whose name ends in `_hz` or `_baud`; no alternative unit fields (design 5.1, 10).
- Operation schemas: `additionalProperties: false`, every field required, kinds as enums (design 5.1).
- Operation errors name the field and the acceptable range, and propose a corrected value where the design says so (design 5.1, 10).
- No silent pre-emption of a held port; conflicts are errors naming the holders (design 4.1).
- Jobs, ids and context survive node restart (design 4.2).
- `cargo test --workspace` passes with no hardware and no network.
- Licence: Apache-2.0 (author's call within the design's "MIT or Apache-2.0").
- Build the minimum (ponytail ladder): reuse before stdlib before new dependency before new code.

## Review Focus

1. A SigMF file whose `core:datatype` is unsupported (for example `rf32_le`): the file source must refuse with an error naming the datatype, not panic or read garbage. Test in Task 5.
2. `source.ensure` for a frequency outside the port's declared tuning range: the error must name `center_hz`, the range, and (when the value looks like dropped zeros) the proposed value. Test in Task 9.
3. A graph document referencing a stage kind that is not registered: `graph.put` and `job.start` must reject it by name before anything runs. Test in Task 7 and Task 8.
4. State directory containing a job file from a previous run whose source no longer exists: node start must not fail; the job is listed in state `failed` with the reason. Test in Task 8.
5. A selection whose time span is older than the ring buffer holds: `classify`/`iq.read` return an error stating the earliest available time, not an empty or partial buffer presented as complete. Test in Task 4.

### Task 3: Port trait and lease manager

**Files:**
- Create: `crates/zeta-core/src/port.rs`, `crates/zeta-core/src/lease.rs`
- Modify: `crates/zeta-core/src/lib.rs`
- Test: `crates/zeta-core/src/lease.rs` (unit tests)

**Interfaces:**
- Consumes: `types::*`.
- Produces:
  - `pub struct Tuning { pub center_hz: Hz, pub bandwidth_hz: Hz }`.
  - `#[async_trait] pub trait Port: Send + Sync { fn id(&self) -> &SourceId; fn capabilities(&self) -> &Capabilities; async fn tune(&self, t: Tuning) -> Result<Tuning, PortError>; fn current(&self) -> Option<Tuning>; fn subscribe(&self) -> IqReceiver; }` where `pub type IqReceiver = tokio::sync::broadcast::Receiver<IqBlock>` and `pub struct IqBlock { pub t0: Timestamp, pub sample_rate_hz: Hz, pub center_hz: Hz, pub samples: std::sync::Arc<[num_complex::Complex<f32>]> }`.
  - `pub enum PortError { OutOfRange { field: &'static str, value: u64, min: u64, max: u64, suggested: Option<u64> }, Unsupported(String), Io(String) }` (thiserror).
  - `pub struct LeaseManager` with `fn new() -> Self`, `fn ensure(&self, port: &dyn Port, holder: JobId, want: Tuning) -> Result<Tuning, LeaseError>`, `fn release(&self, holder: &JobId)`, `fn holders(&self, source: &SourceId) -> Vec<(JobId, Tuning)>`.
  - `pub enum LeaseError { Conflict { source: SourceId, holders: Vec<JobId>, current: Tuning, options: Vec<String> }, Port(PortError) }`.
- Rule (design 4.1): `ensure` succeeds without retuning if `want` fits inside `current` (same centre or want's band within current's band); if the port is unheld it tunes; if held and `want` does not fit it returns `Conflict` with `options` = `["stop one of the holders", "widen capture to N Hz" if N ≤ max_bandwidth_hz, "run a scan job"]`. Never retunes a held port.
