# Speech on a Channel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transcribe speech from any job that produces audio, now or later (the four analogue demodulators today, digital voice decoders tomorrow), into text events pinned to that channel: one generic `transcribe` job that attaches to a running job's audio stream, behind a cleaning chain (denoise, voice gate), a pluggable speech backend that may run on this host or another node's, English first with the language carried end to end, and a slot for a heavier source-separation stage.

**Architecture:** Audio frames gain a `channels` field so every consumer can take mono or interleaved multi-channel at any rate. Three new stages compose after any audio producer: `denoise` (RNNoise via the pure-Rust `nnnoiseless`, in `zeta-dsp`), `vad` (an energy-over-noise-floor voice gate, in `zeta-dsp`) and `transcribe` (new crate `zeta-speech`: accumulates an utterance, downmixes and resamples to 16 kHz mono, encodes WAV, calls a `SpeechBackend`). Instead of a job kind per demodulator, an **attached job** reads another job's output stream: a core `stream_in` stage subscribes to the bus, an attached job holds no radio lease, and a new op `job_attach { kind, job, language }` creates it; `transcribe` is the first attachable kind and any future audio producer (a DMR, D-STAR or M17 decoder) gets transcription for free. Two backends ship: `SocketBackend` (the existing `local-voice` line protocol) and `NodeBackend` (another node's `POST /stt`), and `zeta-ws`'s `/stt` is rebuilt on the same trait. The separation upgrade path is proven by an external audio-to-audio plugin (Python SDK) swapped into the chain with `graph_put`.

**Tech Stack:** Rust 2024 (`zeta-core` stream_in + attach, `zeta-dsp` + `nnnoiseless` 0.5, new `zeta-speech` with tokio net, `zeta-ws`, `zeta-client`, `zeta`), vanilla JS UI, Playwright scenarios, the Python plugin SDK, `local-voice` (`bin/voiced`, Parakeet via sherpa-onnx, English only) as the real daemon.

**Spec:** `docs/superpowers/specs/2026-10-18-zetasdr-design.md` sections 1 ("voice-only-filtered speech-to-text overlaid on the channels it came from"), 4.1 (jobs compose: demod, transcribe, overlay; audio is a post-demod content stage), 4.8 (external processes for heavy stages), 5.1 (resources addressable by stable ids: a job's streams), 5.4 (voice: `local-voice` Parakeet daemon), 7 (text ribbons pinned to the channel).

## Global Constraints

- `zeta-core` gains no dependency. Core changes are exactly: `Payload::Audio` gains `channels: u16` (interleaved; 1 everywhere today), `JobRecord` gains `#[serde(default)] input: Option<JobId>` (format stays 1), the `stream_in` stage, the `JobAttach` op, `JobKind::Transcribe`, and the no-lease launch path for attached jobs.
- An attached job never touches the radio: no lease, no tune, no ring. Its `source` and `tuning` are copied from the input job at attach time (so overlays pin its ribbons to the same channel) and its graph is `stream_in {"job": <id>, "kind": "audio"}` followed by the kind's chain. It ends `Stopped` when the input job's stream closes, `Failed` with `input job <id>: <reason>` when that job is not running at attach or resume. `job_start` refuses `kind: transcribe` with `OpError::Other("transcribe attaches to a job: use job_attach")`.
- `job_attach { kind: JobKind, job: JobId, language: string|null }`: `kind` must be attachable (`transcribe` only in this plan; the `JobKind::attachable()` predicate exists for the next ones); `language` is BCP-47 (`^[a-z]{2,3}(-[A-Za-z0-9]{2,8})*$`), `null` means `en`; the input job must be `running` and have exactly one `audio` output stream (an input job with none is `OpError::Other("job <id> has no audio stream")`; with several, the attach takes the last audio stream in the input job's graph order, documented).
- The speech backend is chosen by the node's operator, never by a job parameter: global flags `--stt-socket PATH` (moved from `serve`-only; env `ZETA_STT_SOCKET`; default `$XDG_RUNTIME_DIR/voiced.sock` when it exists) or `--stt-node URL` (secret from `ZETA_STT_NODE_SECRET`, never printed); both given is a usage error (exit 1). The `transcribe` stage and `POST /stt` use the same backend; with none a transcribe job fails with reason `transcribe: this node has no speech backend (--stt-socket or --stt-node)` and `/stt` keeps answering 503.
- The `local-voice` daemon protocol is unchanged: `file:<absolute wav path>\n` → `ok:<text>\n` or `error:<msg>\n`; it serves English only, so `SocketBackend::languages()` is `["en"]` and another language fails before the daemon is contacted. `NodeBackend` forwards `language` as the `lang` query parameter of `POST /stt`; `/stt` answers 422 `unsupported` naming the backend's languages when it cannot serve one.
- Audio contract between stages: `Payload::Audio { sample_rate_hz, channels, samples }`, interleaved f32 in ±1; a stage derives its timing from the first frame's rate and channel count and fails with `sample_rate_hz changed from X to Y` (or `channels changed`) on a mid-run change; `denoise` and `transcribe` downmix (channel mean) and resample internally (`zeta_dsp::resample::Resampler`); `vad` works at the input rate on the downmix but forwards the original frames.
- Events carry `"protocol"` (`"vad"`, `"transcript"`), keys sorted as serde writes them.
- No stage blocks the bus: the backend call runs in its own task with a bounded queue of 2 pending utterances; a third arriving while two wait is dropped and reported as a `transcript` event with `"dropped": true`.
- Licences: `nnnoiseless` is BSD-3-Clause with the model weights embedded (note it in README); EasyEffects is not used (GPL, desktop-session bound).
- Every task that changes an op, kind, flag or note regenerates `AGENTS.md` and `skills/zetasdr/SKILL.md` and runs `cargo test -p zeta --test agents_md --test transports`.
- Gate per task: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, the crate's tests; final gate `cargo test --workspace --no-fail-fast` (no `FAILED`, no `ui e2e skipped`). Temp files under the job's tmp directory, never `/tmp`; Python via `python3 -I` except the Playwright runner.

## Review Focus

1. A daemon that answers slowly or never: an utterance must not stall the audio chain, and the job must end with a clear reason when the backend is unreachable (not hang). Pinned in Task 5 (timeout and unreachable-socket tests).
2. The input job stops, restarts under `graph_put` (new stream ids), or is gone at node restart: the attached job must end or fail with a reason naming it, never spin on a closed stream or hold a stale id. Pinned in Task 6 (stop, graph_put and restart tests).
3. Music or a steady tone on a broadcast channel: the gate must not keep the transcriber busy forever on non-speech. Pinned in Task 4 (steady-tone and silence tests) and Task 5 (max utterance length).
4. A language the backend cannot serve: the request must fail early and say which languages the backend has. Pinned in Tasks 1 and 5.
5. The forwarding node loop: a node whose `--stt-node` points at itself, or two nodes pointing at each other, must not recurse. Pinned in Task 1 (`/stt` refuses to forward a request that already carries `X-Zeta-Stt-Hop`; `NodeBackend` sets it).
