# Speech on a Channel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Transcribe speech heard on any demodulated channel into text events pinned to that channel, through a cleaning chain (denoise, voice gate) and a pluggable speech backend that may live on this node's host or on another node's, English first with the language carried end to end, and with the chain open to a heavier source-separation stage later.

**Architecture:** Three new stages compose after any audio demodulator: `denoise` (RNNoise via the pure-Rust `nnnoiseless`, in `zeta-dsp`), `vad` (an energy-over-noise-floor voice gate written here, in `zeta-dsp`), and `transcribe` (in a new crate `zeta-speech`: accumulates an utterance, resamples to 16 kHz, encodes WAV, calls a `SpeechBackend`). Two backends ship: `SocketBackend`, the existing `local-voice` line protocol (`file:<wav>` → `ok:<text>`), and `NodeBackend`, another ZetaSDR node's `POST /stt`, so a node without a daemon forwards to one that has it; `zeta-ws`'s own `/stt` is rebuilt on the same trait. Four job kinds (`wfm_transcribe`, `fm_transcribe`, `am_transcribe`, `ssb_transcribe`) append the speech chain to the four existing audio graphs; `job_start` gains a nullable `language`. The separation upgrade path is proven by an external audio-to-audio plugin (Python SDK) swapped into the chain with `graph_put`.

**Tech Stack:** Rust 2024 (`zeta-dsp` + `nnnoiseless` 0.5, new `zeta-speech` with tokio net, `zeta-core` kinds, `zeta-ws`, `zeta-client`, `zeta`), vanilla JS UI, Playwright scenarios, the Python plugin SDK, `local-voice` (`bin/voiced`, Parakeet via sherpa-onnx, English only) as the real daemon.

**Spec:** `docs/superpowers/specs/2026-10-18-zetasdr-design.md` sections 1 ("voice-only-filtered speech-to-text overlaid on the channels it came from"), 4.1 (jobs compose: demod, transcribe, overlay; audio is a post-demod content stage), 4.8 (external processes for heavy stages), 5.4 (voice: `local-voice` Parakeet daemon), 7 (text ribbons pinned to the channel).

## Global Constraints

- `zeta-core` gains no dependency: four `JobKind` variants, one nullable `language` field on `JobStart` (BCP-47 string such as `en`, `de`; `null` means `en` for transcribe kinds and must be `null` for every other kind, like `sideband`), and the graphs composed by name.
- The speech backend is chosen by the node's operator, never by a job parameter: global flags `--stt-socket PATH` (moved from `serve`-only; env `ZETA_STT_SOCKET`; default `$XDG_RUNTIME_DIR/voiced.sock` when it exists) or `--stt-node URL` (secret from `ZETA_STT_NODE_SECRET`, never printed); both given is a usage error (exit 1). The `transcribe` stage and `POST /stt` use the same backend; with no backend a transcribe job fails with reason `transcribe: this node has no speech backend (--stt-socket or --stt-node)` and `/stt` keeps answering 503.
- The `local-voice` daemon protocol is unchanged: `file:<absolute wav path>\n` → `ok:<text>\n` or `error:<msg>\n`; it supports English only, so `SocketBackend::languages()` is `["en"]` and a non-English request fails before the daemon is contacted. `NodeBackend` forwards `language` as the `lang` query parameter of `POST /stt`; `/stt` answers 422 `unsupported` naming the backend's languages when it cannot serve one.
- Audio contract between stages: `Payload::Audio { sample_rate_hz, samples }` mono f32 in ±1; every stage derives its timing from the first frame's rate and fails with `sample_rate_hz changed from X to Y` on a mid-run change; `denoise` and `transcribe` resample internally (`zeta_dsp::resample::Resampler`), `vad` works at the input rate.
- Events carry `"protocol"` (`"vad"`, `"transcript"`), keys sorted as serde writes them.
- No stage blocks the bus: the backend call runs in its own task with a bounded queue of 2 pending utterances; a third arriving while two wait is dropped and reported as a `transcript` event with `"dropped": true`.
- Licences: `nnnoiseless` is BSD-3-Clause with the model weights embedded (note it in README); EasyEffects is not used (GPL, desktop-session bound).
- Every task that changes an op, kind, flag or note regenerates `AGENTS.md` and `skills/zetasdr/SKILL.md` and runs `cargo test -p zeta --test agents_md --test transports`.
- Gate per task: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, the crate's tests; final gate `cargo test --workspace --no-fail-fast` (no `FAILED`, no `ui e2e skipped`). Temp files under the job's tmp directory, never `/tmp`; Python via `python3 -I` except the Playwright runner.

## Review Focus

1. A daemon that answers slowly or never: an utterance must not stall the audio chain, and the job must end with a clear reason when the backend is unreachable (not hang). Pinned in Task 4 (timeout and unreachable-socket tests).
2. Music or a steady tone on a broadcast channel: the gate must not keep the transcriber busy forever on non-speech. Pinned in Task 3 (steady-tone and silence tests: no speech segments after the floor settles) and Task 4 (max utterance length).
3. A language the backend cannot serve: the request must fail early and say which languages the backend has. Pinned in Tasks 1 and 4.
4. The forwarding node loop: a node whose `--stt-node` points at itself, or two nodes pointing at each other, must not recurse. Pinned in Task 1 (`/stt` refuses to forward a request that already carries the `X-Zeta-Stt-Hop` header; `NodeBackend` sets it).
5. A speech backend swapped at runtime (the daemon restarts): the next utterance reconnects rather than the job dying on the first failure. Pinned in Task 4 (one failed utterance emits an error event, two consecutive failures fail the job).

## Live acceptance (controller, after the final review)

Needs a speech daemon reachable by a node. Preferred: `local-voice`'s `bin/voiced` running on the field host as the `sdr` user (`uv sync` in a clone under `~/zetasdr/`, the Parakeet model in `models/`; the socket at `$XDG_RUNTIME_DIR/voiced.sock`), then `zeta serve --stt-socket` there and `wfm_transcribe` on 100.5 MHz (a talk program was on air at 07:00). Alternative: the daemon on the laptop under a user whose runtime directory this session can read, with a laptop node using `--source-node b210@http://field-host:7979` (200 kHz fits the 250 kHz federation cap) and `--stt-socket`. Either way the install is the operator's; the plan's tests use the fake daemon.
