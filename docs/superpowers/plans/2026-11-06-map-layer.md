# Plan 32: The map layer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When a signal is measured, the node scores the register's licensed transmitters against it and publishes one `origin` record; the page lights those sites on a Map that is a tab beside the radios, with bearings from whichever receiver heard the signal (the station, or a KiwiSDR's own position), and the panes dock under the main view or in the right column.

**Architecture:** Node side first: `Allocation` gains `callsign` and the provider trait a per-call vantage (`allocations_from`); `Port::position` and `SourceInfo.position` are filled by the KiwiSDR source from its `/status` or by the generic `--source-position ID=LAT,LON[,ALT_M]`; a new `node/origin.rs` grades `allocation_match`'s tests into a score, answers `origin_lookup`, publishes the `origin` event and keeps `job_context.origins`; identify, classify and the watch carry `origins`; a per-job watcher confirms a lit site from a decoded callsign. Page side: a `main: rf|map` policy puts the Map in `#tabs` and swaps it for the waterfall in `#main`; a `dock: auto|bottom|right` policy moves `#pane` into `#side` as a third collapsible section; `map.js` draws sites, bearings, the source marker and the fade; an in-process register stub joins the e2e harness. The RF thumbnail is last and droppable.

**Tech Stack:** Rust (tokio, serde, schemars; axum in the test stubs), vanilla JS page (Leaflet vendored), the Playwright e2e suite in `crates/zeta-ui/tests/e2e/ui.py`.

**Spec:** `docs/superpowers/specs/2026-11-06-map-layer-design.md` (all of it; the operator's decisions are section 9, the author's calls section 10).

## Global Constraints

- Every op field is required and unknown fields are rejected (`deny_unknown_fields` on `Op`); a nullable op field uses `#[serde(deserialize_with = "crate::modes::nullable")]` plus `#[schemars(required, schema_with = "crate::types::nullable::<T>")]` as `BitsStart.modulation` does (`crates/zeta-core/src/ops.rs`).
- New fields on persisted or strict records (`Allocation.callsign`, `SourceInfo.position`, `Subject.identity`, `Layout.dock`) are `#[serde(default)]` with a nullable schema; `Allocation` keeps `require_all`, `SourceInfo` lists the new field in `require_worker`, so older files and nodes keep loading and the schema still requires every field.
- Numbers from the spec are named constants, never literals in logic: `ORIGIN_SITES = 50`, `ORIGIN_WIDTH_FULL = 0.4`, `ORIGIN_WIDTH_HALF = 0.2`, `ORIGIN_WIDTH_NONE = 0.1`, `ORIGIN_WIDTH_RANGE = (0.5, 1.5)`, `ORIGIN_WIDTH_LOOSE = (0.25, 4.0)`, `ORIGIN_MODULATION_FITS = 0.4`, `ORIGIN_MODULATION_UNKNOWN = 0.2`, `ORIGIN_REACH_IN = 0.2`, `ORIGIN_REACH_UNKNOWN = 0.1`, `ORIGIN_SUMMARY_SITES = 3`, `ORIGIN_FADE_S_DEFAULT = 300` (page: `view.js`), `DOCK_SHARE_DEFAULT = "40%"` (CSS token), `RF_THUMB_W = 240`, `RF_THUMB_H = 120`, `RF_THUMB_FPS = 2`.

## Calls made in this plan (the builder's, on the spec's silence)

1. The vantage is `Option<&Station>` on the trait, not a new `Vantage` type crossing the crate boundary: a source position is wrapped as a `Station` with `Station::default_antennas` and `alt_m` 0 when unknown, so `acma.rs`'s reach rule applies unchanged.
2. The Kiwi's status is fetched inside the session after `SET auth` is accepted and before the first `SND`, once per connection, over a hand-written `GET` on `TcpStream` (no HTTP client dependency); a failed fetch never clears a position already known.
3. `SourcePosition.from` is `status | configured`; `Port::position` reports only what the port itself read, and the node overlays `--source-position` where the port reports none, so `source_list` shows a configured position before the first connection and the status one wins once it exists.
4. `job_modulation` for `wfm_demod` is `["wfm"]` (the layer-1 label), and an `identify` job's own modulation is its verdict's label when it has one, else `[]`.
5. The `origin` event's `summary` is computed by the node once (`origin::summary`) and the page prints it verbatim; a confirmed republish replaces the job's set on the page (same key).
6. The Map tab is appended by `renderTabs` on every `source_list` render; `syncTabs` ignores it; the selected source's tab carries `kept` while `main` is `map`.
7. The waterfall is `visibility: hidden` (not `display: none`) while the Map is shown, so its canvases keep their size and no resize cascade runs on return; `waterfall.js` skips painting under `html[data-main="map"]`.
8. The right dock is a DOM move of `#pane` into a section built by `app.js`, not a second host in `panes.js`; the section's fold is page memory and `pane none` clears it.
9. The register stub moves into `zeta-ext` behind `test-fake` so the e2e harness and the acma tests share one; the harness sets the demo station with `station_set` after `serve` is up (the no-station scenario clears and restores it).
10. The fake_pos job is the e2e's lit-site job: its two events two seconds in are the job's last activity, so `origin_fade_s 2` empties the map within about four seconds.
11. The thumbnail paints with `drawImage` from the waterfall canvas at two frames a second; no second spectrum subscription.
