# UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A browser UI served by the node itself: a scrolling waterfall with channel-pinned labels and decoded-text ribbons, a context menu that emits the same operations the agent does, an agent pane that shows every operation verbatim, a jobs list, a command line with a microphone, a graph view of a job's document, and a narrow renderer for phones, all clients of the plan-3 websocket.

**Architecture:** The node gains three small server pieces (an `ops` event stream that logs every applied operation, browser-friendly websocket authentication, and `POST /ask` and `POST /stt` routes that run the plan-3 agent and the `local-voice` daemon). A new dependency-free crate `zeta-ui` embeds a plain HTML/ES-module/CSS app that `zeta-ws` serves under `/ui/`. One app, two renderers: a CSS/JS footprint switch chooses wide (side pane) or narrow (overlay-only). Browser tests drive the real app with Playwright against a real `zeta serve` on file fixtures.

**Tech Stack:** Rust 2024 (axum 0.8, tokio), vanilla JavaScript ES modules with `<canvas>` and WebAudio (no bundler, no npm), Python Playwright (already installed on the dev box with a cached Chromium) for end-to-end tests.

**Spec:** `docs/superpowers/specs/2026-10-18-zetasdr-design.md` sections 5.2, 5.4, 7, 8 item 4; mockup `/Projects/ham/.superpowers/brainstorm/2212856-1792308507/content/waterfall-layout.html` (the user chose option C: both renderers, switched by footprint).

## Global Constraints

- `zeta-core` gains no dependency (`no_privileged_deps` keeps passing; `egui`/`tauri` are on its ban list and stay out of every crate: this UI is a web client).
- "The UI is a client of the node's websocket; nothing is 'desktop only' by accident." Every UI action is an operation from section 5.1 sent to `POST /op`, or a stream subscription; no new operation shapes.
- "One operation invoked from the GUI context menu and the same operation invoked by an LLM through MCP, hitting the same code path, with the call visible in the transcript pane" (section 8 item 4): the `ops` stream is the single source of the transcript's tool calls, whatever transport applied them.
- "Nothing is exposed without a shared secret" (plan 3): static assets under `/ui/` are the only unauthenticated route; every operation, stream, `/ask` and `/stt` stays behind the bearer secret or its websocket equivalent.
- LAN only; `is_lan` unchanged.
- Voice: "v1 uses the existing `local-voice` Parakeet daemon for speech-to-text" (5.4): the node forwards audio to `voiced.sock`; no cloud speech API, no Web Speech API.
- Strict op schemas unchanged; the `ops` stream payload is the serialized `Op` and its result/error exactly as `POST /op` would return them, truncated only by size.
- CI runs on loopback with file fixtures; the browser test runs when Python Playwright and its Chromium are present and reports a skip reason otherwise (the dev-box gate must not skip).
- Gate: `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo test --workspace --all-features`, `zeta agents-md --check`, `--skill --check`.
- Build the minimum: no bundler, no framework, no TX chain editing, no multi-source waterfall tiling, no agent streaming (the final answer arrives when the run ends; the tool calls arrive live through `ops`).

## Review Focus

1. A browser tab that stalls (background tab, slow laptop) must not take the node down or drop other subscribers: the text websocket already drops the slow socket after `ws_send_timeout`; the UI must reconnect and resubscribe without duplicating jobs. Test: Task 7 `waterfall_reconnects_after_socket_close`.
2. A wrong secret typed in the login box must give a clear message and no half-connected state (no stray websockets, no spectrum job started). Test: Task 6 (browser) `wrong_secret_shows_error_and_starts_nothing`.
3. Closing the tab must not leave the UI's spectrum job running forever on the node: the UI reuses an existing spectrum job on the source when one exists and stops its own on `pagehide`; a leaked job is visible in the jobs list. Test: Task 7 `ui_spectrum_job_is_reused_not_duplicated`.
4. A large operation result (`schema`, a 1000-frame `stream_tail`) on the `ops` stream must not exceed the 64 KiB websocket text limit and kill the subscriber. Test: Task 1 `large_results_are_summarised_on_the_ops_stream`.
5. The microphone path when no `voiced` daemon is present (any host that is not the laptop) must fail with a visible "no speech daemon" message, not a hang. Test: Task 4 `stt_without_daemon_is_503`, Task 11 (browser) `mic_without_daemon_shows_message`.

Conventions used by every task:

- The `ops` stream: kind `Event`, provenance `source: SourceId("node")`, `job: None`, `channel: None`; discoverable as the one `stream_list` entry whose provenance source is `node`. Payload: `{"op": <Op as JSON>, "outcome": "ok" | "error", "result": <OpResult JSON> | "error": <OpError JSON>, "elapsed_ms": u64, "transport": "local"}` (transport is a fixed string in this plan; the field exists so plan 3's adapters can label themselves later). A result whose JSON exceeds `OPS_RESULT_LIMIT_BYTES = 8192` is replaced by `{"result": "<variant name>", "truncated": true, "bytes": n}`.
- Browser websocket auth: the client opens `new WebSocket(url, ["zeta", "zeta.bearer." + base64url(secret)])`; the server accepts the upgrade when either the `Authorization` header or that subprotocol carries the secret, and answers `Sec-WebSocket-Protocol: zeta`. `base64url` is unpadded.
- Footprint: `narrow` when the viewport width is below `NARROW_MAX_PX = 700` or the page is opened with `?footprint=narrow`; `wide` otherwise, or with `?footprint=wide`.
- The UI's own jobs are started with the `spectrum` kind on the whole capture band of the selected source and remembered in `sessionStorage` under `zeta.uiJobs`; before starting one the UI looks for a running `spectrum` job on that source in `job_list` and reuses it.
- Test secret everywhere: `ui-secret-0123456789`. Fixtures: the tone (`write_tone`) and the APRS recording (`zeta_dsp` fixtures, as `crates/zeta/tests/cli.rs` already uses).
