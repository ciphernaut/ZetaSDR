# Themes Implementation Plan (plan 26)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Themes become folders (`theme.json` + `style.css` + files): the node loads the built-ins and the operator's `--themes-dir`, lists them with `themes_list`, serves them under `/ui/themes/<id>/`, and the page applies any ready theme; console and plain move into that format unchanged, and four new built-ins ship: cyberpunk, terminal, psytrance, vibecoder.

**Architecture:** A `themes` module in zeta-core parses and validates a theme folder, wraps its `style.css` (tokens and layout first, the file scoped by native CSS nesting, `@font-face`/`@keyframes` hoisted) and holds the result in a `ThemeRegistry`, built-ins first (embedded from the repo-root `themes/`, beside `modes/`), then the operator's folder, a broken one never stopping the node. The node gets the registry through a setter (no `NodeConfig` field); zeta-ws serves its files outside auth like the rest of `/ui/`. The page links the active theme's `style.css`, reads its `theme.json` for `layout` and `ramp`, and asks `themes_list` for the choices; the core `style.css` keeps layout and neutral (plain) defaults only.

**Tech Stack:** Rust (zeta-core loader and op, zeta CLI, zeta-ws axum route, serde, thiserror, schemars), vanilla ES modules and CSS in `crates/zeta-ui/web`, Playwright scenarios in `crates/zeta-ui/tests/e2e/ui.py` driven by `crates/zeta/tests/ui.rs` (`ZETA_UI_ONLY=a,b`), Pillow for screenshot diffs, SIL OFL fonts.

**Spec:** `docs/superpowers/specs/2026-11-03-themes-design.md` (read it first; section numbers below refer to it). Where this plan departs from it, "Rulings on the spec" at the end says why. Those rulings bind.

## Global Constraints

- Word rule (operator): no franchise names or marks, and not the words "hacker" or "APT", anywhere in code, CSS, theme names, docs or commit messages. `git grep -niE 'hacker|\bAPT\b'` and the plan 24 word list (the words commit `22db49e` removed from `TODO.md`) must be empty on every commit. The console look is described by its parts: elbowed frame, pill bars with dark text, condensed face.
- Theme ids and names: `console` ("Console"), `plain` ("Plain"), `cyberpunk` ("Cyberpunk"), `terminal` ("Terminal"), `psytrance` ("Psytrance"), `vibecoder` ("Vibecoder"). `console` is the default and the fallback.
- `id` matches `^[a-z][a-z0-9_-]{0,31}$` and equals the folder name.
- `theme.json`: unknown fields rejected; every field required except `fonts`. `footprints` is refused today (spec 4.6), as any unknown key.
- `layout.ribbon_tilt_deg` -30..=30. `ramp`: 2-16 stops, `t` strictly ascending, first exactly 0, last exactly 1, channels 0-255.
- Token values: any length; refused when containing `;`, `{`, `}`, `<` or `url(` (case-insensitive). Unknown token keys refused naming the key.
- `style.css` at most 1 MiB (1 048 576 bytes); refusal text `style.css: <n> bytes, more than the 1 MiB limit`. `@import` refused. A `url()` that is absolute (`/`), has a scheme other than `data:`, contains a `..` segment, or names a file not in the folder is refused. `data:` URLs pass untouched.
- Startup line for a broken theme: `zeta: theme <id> (<path>): <field>: <error>`.
- CSP in `crates/zeta-ws/src/ui.rs` unchanged. Theme files are served under `/ui/themes/<id>/<path>` without the bearer, with the page's CSP, `nosniff` and `Cache-Control: no-cache`.
- Browser floor: Chrome 120, Firefox 117, Safari 17.2 (README and `docs/themes.md`).
- Fonts: SIL OFL 1.1 only, each with its `OFL-<Family>.txt` beside it in the theme folder. Downloaded from the font's upstream repository or Google Fonts; record the source URL and version in a comment line at the top of the OFL file's neighbour `FONTS.md` in that folder.
- Every animation in a theme sits under `@media (prefers-reduced-motion: no-preference)`.
- Built-in body text (`--text` on `--bg` and on `--bar`) meets WCAG AA (4.5:1); `--dim` meets 3:1. Built-ins write these four tokens as `#rrggbb`.
- Ops: every task that changes an op regenerates `AGENTS.md` (`cargo run -p zeta -- agents-md > AGENTS.md`) and `skills/zetasdr/SKILL.md` (`cargo run -p zeta -- agents-md --skill > skills/zetasdr/SKILL.md`).
- Gates per task: `cargo fmt -p <each touched crate> -- --check` (per crate; the nested worktree breaks `--all`), `cargo clippy --workspace --all-targets --all-features -- -D warnings`, the task's tests, and the task's scenarios via `ZETA_UI_ONLY=<names> cargo test -p zeta --test ui`.
- Existing e2e assertions that change, and only these: `ui.py:1135-1136` (`view set theme neon` error now lists every ready theme: assert it contains `console`, `plain` and `terminal`) and `ui.py:1142` (`#mic` radii move with the console CSS but keep their values). Any other existing scenario that fails is a bug in the build.
- Temp files under the job's tmp directory (`$CLAUDE_JOB_DIR/tmp`), never `/tmp`. Python via `python3 -I` except Playwright; the Pillow diff runs through uv (`uv run --script crates/zeta-ui/tests/e2e/shotdiff.py ...`, the script declaring `pillow` in PEP 723 inline metadata), never a system package.
- Commits on the plan's branch, one per task, with the message the task names. No merge and no deploy in this plan.

### Task 2: Wrapping a theme's style.css (Opus)

**Files:**
- Create: `crates/zeta-core/src/themes/css.rs`
- Modify: `crates/zeta-core/src/themes/mod.rs` (`load` wraps `style.css`)
- Test: unit tests in `css.rs`

**Interfaces:**
- Consumes: `ThemeJson`, `ThemeError` (Task 1).
- Produces: `pub fn wrap_style(theme: &ThemeJson, css: &str, files: &BTreeSet<String>) -> Result<String, ThemeError>`; the registry stores its output as the served `style.css` (a theme without `style.css` still gets one: fonts, tokens, layout).

Output, in this order:
1. One `@font-face { font-family: "<family>"; src: url("<file>"); font-weight: <weight>; font-display: swap; }` per `fonts` entry.
2. The file's top-level `@font-face` rules, unchanged.
3. The file's top-level `@keyframes <name>` rules renamed `<id>--<name>`.
4. `[data-theme="<id>"] {` `color-scheme: <dark|light>;` `--ribbon-tilt: <n>deg;` each token `<key>: <value>;` then the rest of the file verbatim, with `animation`/`animation-name` values' identifiers that name a hoisted keyframe renamed, then `}`.

The tokeniser recognises comments, strings (both quotes, escapes), `url(...)` (quoted or bare), at-rule preludes and brace depth; it does not parse selectors. `@import` at any depth → field `style.css`, `@import is not allowed`. Size check first. `url()` rules as in Global Constraints → field `style.css`, `url(<target>): <why>`.

## Rulings on the spec

1. **Built-in theme folders live at the repo-root `themes/<id>/`, not `crates/zeta-ui/themes/<id>/`** (spec 7, author's call 1). The loader is in zeta-core and embeds them as zeta-core embeds `modes/`; zeta-core cannot reach into zeta-ui, and the two built-in data folders sit side by side.
2. **The registry reaches the node through `Node::set_themes`, not a `NodeConfig` field.** About 48 files build `NodeConfig` literally; a setter is the precedent (`set_bank_factory`, `add_knowledge`).
3. **The page applies a theme from its files, not from `themes_list`.** `/ui/themes/<id>/theme.json` and `style.css` are unauthenticated, so the page can apply a stored theme before it has a secret; `themes_list` only fills the choices. `ThemeInfo` therefore carries no `layout` or `ramp`.
4. **`layout.ribbon_tilt_deg` owns the ribbon tilt;** `--ribbon-tilt` is refused as a token and emitted by the wrapper. `--rail-w` stays a token (console narrows it to 14 px in the narrow footprint); `layout.rail` is the on/off switch, mirrored as `<html data-rail>`.
5. **There is no completion in the command bar today** (spec non-goals mention it); `view set theme`'s `describe` text lists the ready themes, and that is the whole of it.
6. **`data:` URLs pass in `style.css`.** They load nothing from elsewhere; the CSP decides what they may be (images yes, fonts no).
7. **Theme fonts live in their theme's folder** with `OFL-<Family>.txt`, not in `web/vendor/`; Antonio moves into `themes/console/`.
8. **A theme without `style.css` still serves one** (fonts, tokens and layout), so `#theme-css` always has a target.
9. **Screenshot diffs mask the waterfall canvas, the status line and the live source numbers;** a 0.1 % / 16-level tolerance absorbs font hinting. Pillow is needed for the diff only and comes through uv (operator, 2026-11-03), never a system package.
